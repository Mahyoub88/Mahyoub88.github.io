One workstation, two applications and the PLC

The retained system uses one computer for the SANY operational HMI, the production-management application and the SQL Server database. The operational application has a saved Modbus RTU connection to the PLC and separate serial interfaces for weighing devices.

Scope
Integrated batching, weighing, mixing and discharge, with a PC-based operator interface and production records.
Software
SANY operational HMI and cncrt.exe production management share the jxc SQL Server database on one computer.
Communications
Saved Modbus RTU link to the PLC and separate serial weighing interfaces. Archive logs identify S7-200 and T600 device families; exact CPU and field I/O mapping remain unconfirmed.

SANY: modes, charging, mixing and discharge

The process graphic places manual/automatic controls near the mixer, with charge/discharge pause buttons and a separate run/stop area. Interpret these controls together with the PLC status and field feedback; the retained screenshot is not a recovered Ladder state machine.

  • The PLC communication path is saved as Modbus RTU on COM1, 38400 baud, 8E1, unit address 2.
  • The PC separately has eight serial weighing ports configured as COM3–COM10 at 19200 baud, 8N1.
  • An archive runtime log separately names S7-200 and T600 device families. It does not prove a one-to-one mapping of logged T600 devices to these ports.
  • Motor, gate, valve, pump and conveyor assignments need an as-built I/O list and wiring drawings. The mimic is a functional presentation, not that list.

How the complete software workflow fits together

  • Maintain the recipe and production task in the management application; keep recipe identity, delivery identity and material targets distinct.
  • Select the task/recipe and configure the batch in the operational HMI.
  • Exchange operational commands/status with the PLC, while the configured serial weighing interfaces provide the weighing communication path.
  • Use the HMI's mixing, charging and discharge functions together with PLC/field status. The exact sequence and interlocks require the missing plant program.
  • Record batch quantities and production context in the shared data layer; review per-pot values and cumulative delivery records in the management application.
  • Use tolerance and in-flight settings as configured engineering parameters. A displayed parameter does not establish a completed calibration or a measured performance improvement.

From recipe to production record

  1. Select production requirements. Recipes and tasks define material targets, batch quantity and delivery requirements.
  2. Prepare dosing and weighing. Operator controls expose tare, target quantity, cycle count, coarse-feed and in-flight compensation settings.
  3. Coordinate plant equipment. The operational HMI exchanges commands and status with the PLC while separate serial interfaces provide weighing-device communication.
  4. Mix and discharge. The available controls include mixing timers, automatic/manual selection, charge/discharge pause and discharge inhibition.
  5. Record and review. The database stores planned and actual material quantities, batches, deliveries, weighing settings, alarms and activity records.

This is a functional reconstruction from operator controls and data records. A complete Ladder state machine, verified interlock matrix and safety circuit have not been recovered.

Weighing and material records

The application distinguishes cement, fly ash, mineral powder, powder additive, liquid additives, aggregate fractions, sand and water. Its records connect recipe targets to actual batch quantities; tolerance and fall settings support weighing adjustment and compensation for material still in transit after feeding stops.
