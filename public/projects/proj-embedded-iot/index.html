PIC Embedded Systems — Peripheral Integration & Persistent Storage

Implemented PIC16-based embedded applications using mikroC and Proteus, integrating sensor acquisition, LCD/keypad interfaces, real-time clocks and control outputs. Applied on-chip EEPROM read/write techniques to retain stored values across power cycles.

System architecture

Implementation scope

PIC16 firmware implements timed acquisition and peripheral interfaces. Timer0 schedules display refresh and measurements, I²C connects the DS1307 clock, and serial interfaces drive shift registers and the graphic LCD.

Timing and peripheral integration responsibilities

This project groups PIC firmware and peripheral implementations: multiplexed displays, timed ADC sensing, the DS1307 RTC, 74HC595 output expansion, keypad access control and the Nokia 5110 display. It is an integration portfolio rather than a claim that every peripheral appears on one physical board. On-chip EEPROM storage and retrieval are included as the persistent-storage workstream. These related implementations are presented together without implying that every peripheral was connected to one physical board.

The central design distinction is between time-critical service and slower foreground work. A display-refresh interrupt advances the active digit; scheduled sampling, conversion, formatting and user-interface updates belong in the foreground where practical. A timing diagram should identify the selected oscillator, timer prescaler and reload before deriving a refresh rate. The public examples explain scheduling, but do not establish those settings for every original build.

Analog conversion depends on the selected PIC, reference voltage, acquisition interval and channel configuration. A raw ADC count is not a calibrated physical measurement until the sensor transfer relationship and reference are known. Likewise, a responsive I2C clock requires both electrical compatibility and correct transaction handling; the NXP reference explains bus behaviour, while the device data sheet determines the actual limits.

The engineering review connects each peripheral to its interface, timing needs and failure symptom. A stuck display, unstable analog value and missing RTC acknowledgement should lead to different checks. Reference snippets remain examples: port assignments, register names, drive currents and peripheral voltage compatibility must be checked against the actual board.

Engineering approach

These are related firmware implementations and peripheral techniques. EEPROM storage and retrieval are covered below as part of this consolidated project. PLC batching remains a separate industrial-control implementation.

Write, verify and restore

The value is stored in on-chip EEPROM rather than ordinary RAM, so firmware can recover it after power loss. Write completion and read-back need to follow the selected PIC device and mikroC library.

Illustrative verification sequence — expected behavior, not a published device-test log
Step Action Expected observation
1 Store the example byte 42 at a valid EEPROM address Write completes
2 Read the same address The returned byte is 42
3 Restart after a power cycle Start-up reads the retained byte
4 Request storage of the unchanged byte Write-on-change avoids a redundant write

Reference snippet

This mikroC-style example comes from the repository explanation. It is not recovered project firmware or a complete device configuration.

void store_byte(unsigned char addr, unsigned char value) {
  if (EEPROM_Read(addr) == value) return;
  EEPROM_Write(addr, value);
  Delay_ms(20);
  if (EEPROM_Read(addr) != value) {
    /* report a write error */
  }
}

Valid addresses, timing, power stability and interrupt handling depend on the device and library. The mikroC EEPROM library documentation describes supported devices and write behavior. Multi-byte persistence needs a defined layout and integrity strategy; a successful single-byte read-back does not establish atomic multi-byte updates.
